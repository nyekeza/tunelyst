# Tunelyst 1.1.64

Memory-stability follow-up to the 1.1.63 test release. This update caps per-player audio buffering, trims and clears the inactive player after transitions, bounds the audio-feature cache (including migration cleanup for older unbounded preference entries), and moves palette sampling to a cancellable, 128-pixel Coil request. Album-art memory caching is now explicitly limited by device memory class, and blurred backdrops use a fixed decode bound.

Player, listener, callback, and ViewModel teardown paths are also hardened so released players and cleared controllers are not retained by service or UI references. These changes address identified retention and allocation paths; they do not by themselves prove that RAM stays flat on every device. Verify repeated track changes on the affected devices before calling the reported force-close issue fixed.
